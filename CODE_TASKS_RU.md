# Создание и доработка кода в чате

Для написания калькулятора, скрипта или сайта библиотека документов не нужна. Нужна загруженная локальная языковая модель. Если она не загрузилась, приложение сообщает об этом прямо вместо ответа об отсутствии документов.

Пример проверки в одном чате:

1. «Создай простой калькулятор с интерфейсом в одном HTML-файле: сложение, вычитание, умножение и деление».
2. Сохраните приложенный calculator.html и откройте его в браузере. Проверьте 2+3=5, 9/3=3, деление на ноль и некорректный ввод.
3. «Добавь кнопку сброса и тёмную тему. Сохрани остальные возможности».
4. Сохраните новую версию файла и повторите проверки. Кнопка должна сбрасывать ввод, а арифметика продолжать работать.

Это пример проверки пользователем, а не утверждение, что локальная модель уже выдала корректный калькулятор на конкретном компьютере.

При отсутствии указанного языка для простого калькулятора с интерфейсом модель получает инструкцию создать автономный calculator.html. Для Python укажите язык явно.

Каждый чат имеет свой активный проект. Последние файлы и предыдущие запросы подаются модели при следующей доработке. Каждое сохранение создаёт новую версию, прежние версии не перезаписываются. Имена неизменённых файлов сохраняются, их содержимое переносится в новую версию. Вложения пользователя остаются нетронутыми.

Проект хранится в подпапке code_project каталога вложений этого чата: current.json указывает последнюю версию, v0001/v0002/... содержат файлы. GUI использует стабильный каталог чата, поэтому состояние восстанавливается после перезапуска приложения и возвращения в тот же чат. В новом чате проект отдельный. Не удаляйте runtime-данные чата, если хотите продолжить его проект.

Приложенные .py, .html, .js и другие поддерживаемые исходники читаются без удаления отступов, HTML-тегов и содержимого script. Можно приложить существующий файл и написать «Исправь код» или «Добавь кнопку сброса». Если меняете программную задачу полностью, используйте новый чат.

Автоматически код не исполняется. Для Python проверяется синтаксис, для JSON — корректность JSON; это не проверка поведения программы. Для HTML/JavaScript и остальных языков выполнение и функциональные проверки остаются пользователю. При некорректной структуре ответа модели или синтаксической ошибке Python новая версия не становится активной. Генерация может требовать уточнения задания или повторной попытки; функциональная корректность зависит от модели.

Режим предназначен для небольших проектов: до 40 000 символов исходников в запросе, простые имена файлов без подпапок. Чтение PDF-нормативов, создание ведомостей и их пошаговое редактирование относятся к другому режиму: данная доработка не добавляет накопление исправлений в спортивной ведомости.

Проверка разработчика: 134 теста выбранных наборов прошли, включая 18 тестов нового режима. Проверены создание без RAG, доработки, восстановление после перезапуска, изоляция чатов, сохранность прошлых версий, чтение HTML-исходников, сообщение об отсутствии модели и отсутствие автоматического исполнения. В тестах ответы модели контролируемые; качество реальной генерации на RTX 4060 здесь не измерялось.
