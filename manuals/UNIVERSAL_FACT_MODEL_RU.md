# Универсальная модель фактов

Версия 1.7.16 добавляет слой `core/knowledge_units.py`. Он нужен, чтобы ChatKodi не превращался в узкий анализатор одного типа документов.

## Базовые понятия

`Mention` — буквальное упоминание в тексте. Например: `склад БК`, `сахар`, `кортизол`, `рБПЛА №11`.

`Entity` — нормализованная сущность. Например: `рБПЛА №11`, `мука`, `болезнь Кушинга`, `i3-10100`.

`Claim` — проверяемое утверждение. Например: `склад БК поражён`, `сахара нужно 150 г`, `выпекать 35 минут`, `кортизол повышен`.

`Qualifier` — уточнение факта: дата, количество, единица измерения, место, температура, условие.

`SourceSpan` — точный источник: документ, чанк, позиция, страница или абзац.

`CountUnit` — что именно считается в статистике: упоминания, факты, документы, цели, шаги, ингредиенты, места, даты.

## Примеры

Военная сводка:

```text
Claim: поражён
Entity: склад БК
Qualifier: дата 15.06.2025
Qualifier: место Полтавка
SourceSpan: 15.docx, нужный фрагмент
```

Рецепт пирога:

```text
Claim: требуется ингредиент
Entity: сахар
Qualifier: 150 г
SourceSpan: recipe.docx, строка рецепта
```

Техническая инструкция:

```text
Claim: установить пакет
Entity: PyQt5
Qualifier: команда pip install PyQt5
SourceSpan: install.md, шаг 3
```

## Инженерное правило

Не надо зашивать в ядро слова вроде `цель`, `поражение`, `метод`. Они могут быть полезны в профильном режиме, но фундамент должен работать и для рецепта, и для договора, и для лекции, и для логов.
