# Автоматизация: путь к 1.9 и 2.0

## Цель 1.9

Версия 1.9 должна стать релизом «пользователь запустил — программа сама поняла, что делать». Ручные настройки остаются, но основа — автоматический режим.

Приоритеты:

- единый установщик лаунчера;
- авто-подготовка приложения из лаунчера;
- авто-выбор CPU/GPU PyTorch;
- авто-выбор модели под RAM, CPU, CUDA и размер корпуса;
- проверка готовности перед запуском;
- понятные сообщения вместо технических ошибок;
- быстрый режим без LLM, если устройство слабое;
- ручной режим для опытных пользователей.

## Идеи для 1.9

### Умный мастер первого запуска

Лаунчер показывает 3 шага:

1. Проверка устройства.
2. Подготовка окружения.
3. Запуск ChatKodi.

Пользователь видит не поток pip-логов, а человеческий статус: «Python найден», «Ставлю библиотеки», «Модели готовы», «Можно запускать».

### Рекомендатор модели

Программа должна не просто показывать список моделей, а подписывать их:

- рекомендуется для этого ПК;
- слишком тяжёлая для CPU;
- подходит для GPU;
- уже скачана;
- можно скачать.

### Режим «не тормозить»

На слабых ПК ChatKodi должен сам выбирать retrieval-first режим: поиск, структурные ответы и источники без попытки грузить тяжёлую LLM.

## Цель 2.0

Версия 2.0 — это уже не просто локальный RAG, а рабочая платформа для документов.

Большие направления:

- модульная архитектура плагинов;
- отдельный сервис индексации;
- очередь фоновых задач;
- нормальная база знаний с фактами, сущностями, утверждениями и источниками;
- стабильный benchmark перед каждым релизом;
- менеджер корпусов документов;
- мультимодальность: изображения, таблицы, аудио, видео;
- полноценный model manager;
- экспорт отчётов в DOCX/PDF/HTML;
- режим «почему такой ответ» как полноценный explainability-layer;
- self-healing diagnostics: программа сама предлагает исправить проблему.

## Главный принцип

Авто — основной режим. Ручные настройки — не обязанность пользователя, а инструмент для тех, кто хочет управлять системой тонко.
