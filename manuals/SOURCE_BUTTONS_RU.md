# Источники ответа: «Показать» и «Открыть»

## Что добавлено

Под ответом ассистента используется компактный выпадающий блок:

```text
▸ Источники ответа • 6
```

По умолчанию он свернут, чтобы не перегружать чат. Если нажать на строку, она раскрывается:

```text
▾ Источники ответа • 6
📄 10.docx    [Показать] [Открыть]
📄 11.docx    [Показать] [Открыть]
📄 12.docx    [Показать] [Открыть]
```

Обе кнопки имеют разный смысл:

- `Показать` — открыть документ внутри ChatKodi во вкладке «Документы».
- `Открыть` — открыть файл во внешней программе системы: Word, PDF-reader, Excel и т.д.

Оформление сделано в общей зеленой палитре ChatKodi: мягкий зеленый акцент, аккуратная рамка, без синих чужеродных кнопок.

## Поведение кнопки «Показать»

Кнопка не запускает внешний редактор. Она:

1. Переключает интерфейс на вкладку «Документы».
2. Выбирает нужный файл в списке корпуса.
3. Показывает текст документа во внутреннем предпросмотре.
4. Если рядом с источником в ответе была цитата, пытается найти и выделить этот фрагмент в тексте.

Пример строки ответа:

```text
1. 15.docx: `рБпЛА №11 (Изюмское направление):`
```

В этом случае `Показать` откроет `15.docx` внутри приложения и попробует сразу перейти к строке `рБпЛА №11 (Изюмское направление):`.

Если точная цитата не найдена, документ всё равно открывается, а в статус-баре появляется честное сообщение, что точный фрагмент не найден в предпросмотре.

## Поведение кнопки «Открыть»

Кнопка `Открыть` использует системный механизм открытия файла. На Windows это обычно Word/Excel/PDF-reader, на Linux и macOS — программа по умолчанию для данного типа файла.

Если файл физически отсутствует или уже был удалён, ChatKodi показывает понятное сообщение об ошибке.

## Как программа понимает, какие документы показать

`gui/main_window/messages.py` ищет в тексте ответа имена файлов в форматах:

- `📚 Источники: 10.docx, 11.docx`
- `📚 Документы-основания расчёта:` со списком ниже
- `1. 15.docx: цитата`
- `1. 15.docx`
- markdown-строки вида `1. **15.docx**`

После этого имя обязательно сверяется с реальными документами в `doc_processor.documents`. Если файла нет в корпусе, элемент не попадает в интерфейс. Это защищает от случайных `file.ext` в тексте ответа.

## Поведение при streaming-ответах

При streaming пузырь ответа создается пустым, поэтому источники нельзя построить сразу. Список источников добавляется после завершения генерации полного ответа, перед меткой времени сообщения.

## Ограничение текущей итерации

Точная навигация сейчас работает по текстовой цитате из ответа. Для идеального перехода к доказательству в будущем нужно хранить в evidence не только имя файла, но и стабильные координаты: `chunk_id`, `paragraph_index`, `page`, `start_char`, `end_char`.
