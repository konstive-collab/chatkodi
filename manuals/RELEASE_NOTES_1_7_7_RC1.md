# ChatKodi 1.7.7-rc1 — CPU/GPU Safe Runtime

Цель сборки: одна версия должна стабильно запускаться как на GPU-машине заказчика, так и на CPU-only тестовой машине с 8 GB RAM.

## Главное

- CPU-only low-RAM профиль теперь уходит в `structured-only` RAG и не пытается автозагрузить LLM.
- LLM Query Planner выключен по умолчанию и автоматически отключается на CPU/low-RAM.
- RAG больше не вызывает lazy-load LLM, если MemoryGuard запретил генерацию.
- Добавлен кэш intent-разбора в `ChatManager` и `QueryPlanner`, чтобы один запрос не анализировался несколько раз.
- EventStore получил лимиты `max_sync_chunks` и `max_sync_seconds`, чтобы первичная синхронизация событий не убивала слабые машины.
- Семантический numpy-search использует заранее нормализованную матрицу эмбеддингов, чтобы не пересчитывать нормализацию всего индекса на каждый запрос.
- Batch size эмбеддингов снижается на CPU/low-RAM.
- Адаптивные лимиты теперь режут retrieval/context/evidence budgets под железо.

## Как тестировать на слабом ПК

1. Запустить программу.
2. Проверить лог `Runtime profile selected`.
   Для CPU/8GB ожидаемо: `academic_safe` или `safe_cpu`.
3. Сначала проверить режим поиска.
4. Потом RAG по точным фактам.
5. Потом RAG по диапазонам/статистике.

На CPU/8GB нормальное поведение: ответы чаще structured-first, без тяжёлой генерации LLM.

## Как тестировать на GPU

На GPU query planner можно включить вручную в `chatkodi_config.json`:

```json
"query_planner": {
  "enabled": true,
  "use_llm_router": true
}
```

Но для стабильной приёмки лучше сначала тестировать с `use_llm_router=false`.

## Важное

Эта сборка не удаляет GPU-ускорение. Она добавляет безопасную деградацию: CPU не падает, GPU может использовать более широкий профиль.
