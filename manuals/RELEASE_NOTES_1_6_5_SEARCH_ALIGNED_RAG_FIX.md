# ChatKodi 1.6.5 — Search-aligned RAG fix

## Что исправлено

- RAG в режиме фрагментов теперь ставит rescue/evidence-чанки в начало контекста, а не прячет их в хвосте.
- Добавлен точечный direct-answer путь для бинарных фактологических вопросов (например: `Использовалось ли ...?`, `Был ли поражен ...?`), если режим поиска уже нашёл сильный answer_rescue/anchor fragment.
- Streaming RAG использует ту же подготовку пакета, что и обычный RAG: один и тот же context + direct answer hint.
- В full-documents режиме блок `FOCUSED_EVIDENCE` теперь подаётся перед основным контекстом, чтобы локальная LLM не игнорировала самый сильный фрагмент.

## Зачем это нужно

Основная проблема была не в самом поиске: режим поиска уже находил правильный фрагмент (`answer_rescue`), но RAG либо ставил этот фрагмент слишком поздно в контекст, либо отдавал ответ на откуп модели, которая предпочитала более слабый кусок документа.

В результате:
- поиск показывал правильный фрагмент;
- RAG отвечал `В документах нет информации` или уходил в более слабый ответ.

## Что менять в поведении не должно

- Небинарные запросы вроде `На каком направлении...` продолжают идти по обычной RAG/LLM-цепочке.
- Базовый retrieval не заменён заново, а только усилен там, где режим поиска уже показал более точный фрагмент.
